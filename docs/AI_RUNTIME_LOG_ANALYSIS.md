# AI 运行日志分析

[文档目录](README.md) · [用量与模型验证](AI_USAGE_AND_MODEL_CHECKS.md) · [测试与验收](TESTING.md)

## 启用与使用

该功能默认开启。超级管理员登录后即可使用，不需要额外环境变量、数据库迁移或日志平台。

超级管理员登录后进入「AI 对话」直接提问，例如「查询最近一小时 ERROR 日志，关键词 TimeoutError，请引用证据并区分事实与可能原因」。不再需要勾选模式或填写独立筛选表单；模型按需调用内置 `query_runtime_logs` 工具，并选择受限查询参数。只有实际收到合法工具调用时，后端才读取日志。

当前模型与配置的接口必须支持 tools/function calling。OpenAI Chat Completions、Responses 和 Anthropic 协议通过现有 LangChain 客户端适配；兼容网关是否支持该能力须实际验证。首次工具路由失败时可给出不保存的普通排查建议，并明确提示未读取日志；已开始读取、显式日志请求或追问失败则报错，不回退到拼接日志提示词或声称已查询日志。旧客户端的 `log_query` 仅作为模型选择参数的提示，不再直接触发文件读取。

「回答依据」按需打开：桌面使用可关闭侧栏，小屏使用抽屉。每次实际查询独立显示条件、匹配数、返回数与截断提示，时间范围和读取边界默认折叠；保留各次查询累计的编号证据。空结果也作为工具结果回传，只表示当前有限范围没有证据，不表示生产系统没有问题。模型判断是排查建议，不是已确认根因，更不是已经执行修复。

等待期间在输入区上方显示请求等待、工具判断、只读查询与证据分析阶段，以及本次请求已等待的秒数。状态由真实事件驱动，不展示虚构进度百分比。日志回答仍在权限校验及整段脱敏后一次性返回，不是逐 token 流式输出。生成时可以编辑下一条问题，发送按钮切换为停止；停止不会清除正在编辑的新草稿。中文输入法确认候选词不会触发发送，Shift + Enter 保留换行。

调用链：当前问题 → `SystemMessage` 策略与脱敏 `HumanMessage` → `bind_tools` → 模型返回 `AIMessage.tool_calls` → 后端校验名称、参数、身份与调用 ID → 只读查询/脱敏 → 对应 `tool_call_id` 的 `ToolMessage` → 模型分析或继续查询 → 校验权限、整段脱敏 → 返回回答与引用。不是解析模型文本中的伪工具 JSON，也不是将日志直接拼入用户提示词。

## 日志追问与故障恢复

一次分析完成后可继续问「缩小到15分钟」「只看同一请求的 ERROR」。服务端返回随机 `log_context_id`；后续 WebSocket 请求或 `ai-chat` 请求带此 ID，只用于补全上次实际查询的筛选条件。本轮仍必须调用工具重新取证，引用编号也从本轮重新开始；不复用旧回答或旧日志正文。HTTP 客户端可从响应中取得下一轮 ID。

临时上下文只包含脱敏后的最后一次实际查询条件，绑定用户和登录会话。单进程最多保留128份，10分钟到期，生成新 ID 时清理过期项；不写 Redis、数据库、长期记忆或浏览器存储。不同用户/登录会话、到期、容量淘汰、后台重启或切换工作进程均统一提示条件失效，要求重新描述完整查询，不自动将模糊追问降级到普通会话。当前通过最近分钟数查询，支持超过一天的归档时间范围；不支持任意绝对起止时间或跨实例日志聚合。

HTTP 认证将已验证的登录会话 ID 传给 AI 服务。非流式聊天入口独立读取并脱离认证用户快照，避免日志授权检查回滚请求事务时过期 ORM 属性，影响后续模型请求；实时权限检查仍直接查询数据库。此快照边界仅用于 AI 聊天，不改变其他后台操作的认证事务行为。

非流式 AI 聊天路由设置 `x-audit-payload=false`，操作审计保留路径、用户、时间和状态等元数据，省略请求和响应正文，避免日志证据、临时上下文 ID 或问题再次落入审计表。其他接口的既有审计策略不变。

输入区明确显示日志追问状态，可「结束日志追问」回到普通知识问答；新会话、成功切换会话、清空显示或离开页面也会清除客户端 ID。退出追问不清除草稿或已选资料。追问与附件/知识库不能混用，界面提前提示，后端也独立拒绝。

取消首次路由12秒及后续单次60秒的额外超时，整个工具循环仍保留90秒请求超时，防止失控循环；用户可随时停止。工具查询次数和模型请求次数不设固定上限。仅尚未查询、没有显式 `log_query`/`log_context_id` 的路由故障可转入普通 RAG；警告随回答显示，整轮不创建/追加会话、不提取长期记忆，不携带日志条件或正文。认证失败、模型限流、配置无效、权限失效、非法调用及读取后的失败不做自动降级。日志路由不自动探测模型能力：状态接口只代表权限。模型配置页提供[手动能力验证](AI_USAGE_AND_MODEL_CHECKS.md)，需要单独发送真实请求才能确认供应商是否支持工具。

WebSocket 错误附带稳定的 `error_code`；不再施加每位管理员10秒的日志查询冷却；供应商自身的限流仍按模型错误返回。若其他错误事件带 `retry_after`，重试按钮显示倒计时并暂时禁用，结束后由用户手动重试，不自动发送；立即日志追问没有该冷却。重试保留原问题、附件/知识库和原临时查询 ID；失效的追问不提供盲目重试，需要重新填写查询条件。

## 数据与安全边界

- 读取本实例 `backend/logs/fastcore.log` 完整活动文件和该目录内 Loguru 轮转的 `.log` / `.log.gz` 归档，包括轮转与压缩碰撞产生的日期、编号后缀。按每个文件打开时的大小快照逐行读取，不再只扫末尾2 MiB，也不将完整文件一次性载入内存；取消会通知读取线程停止。返回 `scanned_files` 与各条记录的 `file`，引用中显示来源文件。`scanned_bytes` 是各文件实际读取的磁盘字节总量（gzip 为压缩字节）；文件内记录经解压后筛选。不聚合其他实例、Nginx、容器、操作/登录审计日志。多实例部署需对齐实例；日志目录须保持私有，不要静态托管。
- 安全读取要求平台支持 `O_NOFOLLOW`、`O_NONBLOCK` 和目录文件描述符。目前面向 Linux/macOS 部署；不具备这些能力的平台（包括当前 Windows 实现）会拒绝读取，不回退到可跟随软链接的路径。
- 时间范围为服务器本地时间，最近分钟数必须为正整数，默认60分钟，不限制为5–1440分钟。默认查询 DEBUG、INFO、SUCCESS、WARNING、ERROR、CRITICAL 全部级别，模型可显式缩小级别；文件日志遵循现有 `LOGGER_LEVEL`，未写入文件的调试日志无法追溯。关键词在整条记录脱敏后以 `casefold()` 忽略大小写进行字面匹配，不支持执行正则、SQL、文件路径或 Shell。关键词长度不再额外截断。旧日志的 cid 只有前8位，并非完整请求 ID 的唯一证明。
- 返回所有完整匹配条目，保留完整多行堆栈；取消40条、单条2000字符、总证据12000字符和最终回答24000字符上限。支持一次模型响应提出多个查询，并继续多轮取证；同一批工具调用先全部校验，再顺序执行，以避免并发共享认证数据库会话，每个调用分别关联 `ToolMessage`。未知工具、非法参数及重复调用 ID 仍拒绝。`truncated` 只标识未写完或无法识别的日志内容，不再表示人为输出截断。所有级别和完整记录会增大模型输入；超过供应商上下文容量时明确失败，不静默删掉证据，需按时间、请求 ID 或关键词缩小查询。
- 每次分析在读取、发送给模型及返回回答前重新检查 Redis 登录在线状态和数据库中的启用/未删除超级管理员身份。取消本地固定查询冷却，立即追问可执行；完整工具循环保留90秒请求超时，取消时不写入结果。多个文件各自固定大小的快照不保证跨文件或并发原地改写的原子一致性。归档在读取前被删除、替换或损坏时明确报错，不伪装为完整查询成功。
- 常见凭据、认证头、Cookie、URL 认证信息、私钥与常见个人信息在查询出口脱敏，模型回答整体再次脱敏后才展示，避免分块切断秘密。文件日志禁用 Loguru 局部变量诊断与扩展回溯，降低新日志泄露风险。
- **自动脱敏不是完整的数据防泄漏系统**。已有日志、任意业务正文、未知格式凭据和商业敏感内容仍可能残留。功能默认开启且没有环境开关，因此生产环境应配置受信任、符合数据合规要求的模型，高敏环境应使用内部模型。不要在问题中主动粘贴秘密。
- 分析不附带知识库、附件、个人资料、历史会话或长期记忆，不保存分析问题、回答或日志片段到会话和记忆。查询审计只记录管理员 ID 与数量，不记录关键词、日志正文或模型异常详情。页面切换、刷新后分析结果会消失；需要保存时由管理员自行选择安全方式。
- 日志文字是非可信证据，不是高优先级指令；本功能没有执行修复、任意读取文件或执行命令的能力。任何后续修改都需人工审核。
- 普通用户不进入工具路由，也不接收日志工具定义。超级管理员每次提问增加一次工具路由模型请求；未调用工具时丢弃路由文本，继续原有知识问答 RAG 链路。这样避免把附件、知识库、个人资料和历史内容带入日志分析。普通问答仍保存会话；前端不提前创建会话，而是接收后端成功事件里的会话 ID。

## 实现选择与验证

复用现有聊天模型边界与 WebSocket 阶段/引用事件，不另建 Agent 框架或 Provider 客户端。参考 CodeVault `ai-provider-compatibility` Pattern 的领域逻辑与供应商兼容边界：`LangChainChatModel.request_tools` 统一工具请求，Service 负责名称白名单、实时授权和有限执行循环，日志模块负责参数契约、安全快照读取、归档解压和完整证据筛选。本轮沿用 CodeVault 的供应商兼容边界，不新增通用工具框架、Provider 配置或新的证据硬上限。拒绝复制供应商适配器，也不引入通用工具注册框架或终端工具。工具角色和返回格式遵循 [LangChain 工具调用文档](https://docs.langchain.com/oss/python/langchain/models#tool-calling)。

可重复检查：

```sh
cd backend
.venv/bin/python -m pytest tests/test_runtime_logs.py tests/test_ai_log_analysis.py tests/test_ai_log_followup.py tests/test_auth_session.py tests/test_ai_chat_ux.py
cd ../frontend
corepack pnpm exec vitest run
corepack pnpm exec vue-tsc --noEmit
node tests/log-analysis-e2e.cjs
node tests/log-followup-e2e.cjs
```

浏览器验收使用隔离 SQLite、模拟 Redis、真实登录/HTTP/WebSocket/文件日志读取和本地确定性模型，经过实际 `bind_tools`/`ToolMessage` 边界，检查自然语言提问、批量与四次连续工具查询、70条 INFO 上下文、完整长堆栈、gzip归档、大小写匹配、立即追问、工具参数、脱敏证据、完整引用预览、不创建或写入会话、明暗主题及响应式布局。协议测试通过 MockTransport 验证三个真实 SDK 的工具定义、调用解析和工具结果序列化，不访问外部供应商。它们不证明生产环境、真实模型的工具选择质量或多实例日志分析已经验收。
