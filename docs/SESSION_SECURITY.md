# 密码变更与会话失效

登录时，服务端用 `SECRET_KEY` 对用户 ID 和当前密码哈希计算 HMAC 指纹，
将指纹保存在 Redis 会话中，不缓存密码哈希本身。HTTP 认证、刷新令牌、
WebSocket 建连及后续消息校验均将会话指纹与数据库当前凭证比较。

- 用户自行修改密码、管理员重置密码或其他入口更新密码哈希后，所有旧会话
  在下一次认证时返回 401，包括发起改密的当前会话；用户需要重新登录。
- 新登录使用当前凭证生成指纹。刷新令牌只延长原会话，不更新凭证绑定，
  因而无法让旧会话恢复。
- 免登录票据在签发时绑定同一凭证指纹，改密前签发的票据无法换取新会话。
  校验失败仍消费该一次性票据，需要重新签发。
- 部署本校验前的 Redis 会话和免登录票据没有指纹，会要求重新登录或重新
  签发；不自动补齐旧凭证绑定。
  无需数据库迁移，也不扫描或批量删除其他 Redis 数据。
- 已通过认证并正在执行的请求不追溯取消。密码变更必须提交成功后才影响
  后续认证；数据库事务回滚不会改变当前凭证。

可重复回归：

```sh
cd backend
uv run pytest -q tests/test_arch_auth_regressions.py tests/test_auth_session.py
```

测试使用临时 SQLite 和模拟 Redis，覆盖两个旧会话、改密/重置、HTTP、
刷新令牌、WebSocket、一次性票据、免登录票据以及新会话成功认证，不代表真实 Redis、
MySQL 或 PostgreSQL 环境验收。
