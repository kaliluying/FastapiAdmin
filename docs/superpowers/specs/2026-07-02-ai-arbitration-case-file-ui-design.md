# AI 劳动仲裁前端界面重构设计

日期：2026-07-02

项目路径：`courseware/ai-arbitration-vue3`

设计方向：B. 案件档案室

## 学习目标

学生通过这次重构要学会三件事：

1. Vue3 前端不是只负责“好看”，它要把业务流程组织清楚。
2. AI 劳动仲裁系统的核心链路是：咨询事实、上传证据、生成文书、人工复核。
3. 界面改版必须保留真实接口逻辑，不能把真实接口、mock 数据和设计扩展混在一起。

## 业务目标

当前课程前端已经具备 AI 咨询、证据上传分析、仲裁申请书生成、导出等能力，但界面更像普通后台三栏工作台。重构目标是把它改成“案件材料整理室”：学生进入页面后能立刻理解自己在整理一个劳动仲裁案件档案，而不是只是在和 AI 聊天。

这次重构解决四个业务问题：

1. 让当前案件、申请人、证据数量、文书入口更明显。
2. 让“咨询 -> 证据 -> 文书 -> 复核”的流程在顶部和右侧都能被看见。
3. 让右侧区域从普通信息栏变成案件摘要、证据材料、复核清单。
4. 让课堂讲解时能围绕同一个案件档案说明前端如何调用后端接口。

## 设计原则

视觉基调是“案件档案室”，不是营销页，也不是通用 SaaS 后台。

1. 使用纸张、档案、表单、印章感的视觉语言，但保持操作效率。
2. 主色采用深赭红或印章红，辅助色使用纸张米白、墨绿色、灰蓝色。
3. 圆角控制在 8px 以内，避免过度柔和。
4. 不使用装饰性渐变球、玻璃拟态或大面积紫蓝渐变。
5. 所有流程按钮和状态都必须服务业务含义。

## 页面结构

主页面继续使用 `HomeView.vue` 作为容器，保留现有三块区域，但改变语义和视觉层级。

1. 顶部：`TopBar.vue`

   展示系统名称“案件材料整理室”，副标题为“劳动仲裁辅助 · 事实到文书”。中间保留三个主流程入口：事实咨询、证据整理、申请书。右侧展示 AI 连接状态、用户入口和退出按钮。

2. 左侧：`HistoryPanel.vue`

   从“咨询会话列表”改成“案件档案列表”。每条会话展示案件标题、案件名、消息数和时间。新建按钮改成“新建案件咨询”，帮助学生理解一次会话对应一次案件材料整理过程。

3. 中间：`MainPanel.vue`

   保留根据 `activeModule` 切换 `ConsultModule`、`UploadModule`、`DocumentModule` 的逻辑。顶部案件头改成更强的案件档案头，展示当前案件、申请人、会话状态和清空对话操作。

4. 右侧：`RightRail.vue`

   从普通侧栏改成案件辅助栏，包含案件摘要、检索依据、证据材料、复核清单和生成申请书入口。证据列表仍然调用真实 `listEvidence` 接口。

5. 底部：`StatusFooter.vue`

   保留系统状态区，但视觉统一到档案室风格。

## 组件改动

第一阶段只改界面，不改数据库模型，不改后端接口。

涉及文件：

1. `courseware/ai-arbitration-vue3/src/styles/main.css`

   重构全局色彩变量、布局尺寸、导航、卡片、聊天气泡、表单、上传区、文书预览等样式。

2. `courseware/ai-arbitration-vue3/src/components/TopBar.vue`

   修改品牌文案、导航显示、连接状态和退出按钮视觉。

3. `courseware/ai-arbitration-vue3/src/components/HistoryPanel.vue`

   修改左侧会话列表的标题、按钮文案和档案式条目样式。

4. `courseware/ai-arbitration-vue3/src/components/MainPanel.vue`

   修改当前案件头部结构，强化案件标题、申请人、模块状态。

5. `courseware/ai-arbitration-vue3/src/components/RightRail.vue`

   重构右侧内容顺序和文案，把“流程进度”改成更适合课堂复述的“复核清单”。

6. `courseware/ai-arbitration-vue3/src/components/modules/ConsultModule.vue`

   优化空状态、AI 回答来源说明、用户和 AI 气泡视觉。

7. `courseware/ai-arbitration-vue3/src/components/modules/Composer.vue`

   优化输入区和建议问题芯片，使其更像案件事实采集入口。

8. `courseware/ai-arbitration-vue3/src/components/modules/UploadModule.vue`

   保留上传、解析、分析逻辑，调整上传区、分析结果和状态徽标视觉。

9. `courseware/ai-arbitration-vue3/src/components/modules/DocumentModule.vue`

   保留文书生成、导出、历史逻辑，调整表单和草稿预览的档案文书感。

## 数据和接口边界

真实接口保留：

1. WebSocket 聊天：`/api/v1/ai/chat/ws`
2. 会话接口：`chatSessionApi.ts`
3. 证据接口：`evidenceApi.ts`
4. 仲裁文书接口：`arbitrationApi.ts`
5. 用户信息和登录状态：`useAuth.ts`、`authApi.ts`、`userApi.ts`

mock 数据保留：

1. `data/mock.ts` 中的示例会话、法律依据、建议问题、流程配置。
2. mock 只用于课程演示和空状态，不冒充真实后端结果。

设计扩展：

1. “案件摘要”和“复核清单”主要是界面组织方式，第一阶段不新增后端字段。
2. 如果后续要把复核清单保存到数据库，需要另开后端模型和迁移任务。

## 错误和空状态

界面必须保留并优化现有错误显示：

1. 登录失效时仍然跳转登录页。
2. WebSocket 未连接时，咨询区显示可理解的错误提示。
3. 证据列表加载失败时，右侧证据区显示后端错误信息。
4. 没有上传证据时，展示“暂无上传记录”，并引导进入证据整理。
5. 没有生成文书时，预览区说明需要先填写事实并点击生成。

## 响应式要求

1. 桌面端保持三栏结构。
2. 1024px 左右压缩右侧栏宽度，保证中间工作区可读。
3. 768px 以下切换为单列或上下结构，避免横向滚动。
4. 375px 手机宽度下，按钮文字不能溢出，表单字段必须单列排列。

## 验证方法

代码实现完成后，需要在 `courseware/ai-arbitration-vue3` 下执行：

```bash
npm test
npm run build
```

还需要启动前端：

```bash
npm run dev
```

浏览器验证页面：

1. 登录后进入首页，顶部显示“案件材料整理室”。
2. 点击“事实咨询、证据整理、申请书”可以切换模块。
3. AI 咨询仍能通过 WebSocket 发送和接收消息。
4. 证据整理仍能选择文件并调用上传分析接口。
5. 申请书页面仍能从证据回填、生成草稿、导出 Word / PDF。
6. 375px、768px、1024px 和桌面宽度下没有文字重叠和横向滚动。

## 讲解说法

可以这样向学生解释：

> 这次重构没有改变后端接口，也没有改变 AI、证据和文书的业务逻辑。我们只是把前端页面从普通后台样式改成“案件材料整理室”。左边是案件档案列表，中间是当前案件的咨询、证据或申请书工作区，右边是案件摘要、证据材料和复核清单。这样做的原因是，劳动仲裁辅助系统不是单纯聊天机器人，而是围绕一个案件，把事实、证据、法律依据和文书草稿串起来。

## 自查问题

1. 为什么这次重构不需要修改后端数据库模型？
2. `RightRail.vue` 里的证据材料列表是真实接口、mock 数据，还是设计扩展？
3. 如果页面变好看了但 WebSocket 聊天不能用了，应该先检查哪个文件和哪个接口？

## 实施边界

本阶段不做以下事情：

1. 不新增后端接口。
2. 不新增数据库表或字段。
3. 不改变证据上传和文书生成的请求体。
4. 不引入新的大型 UI 框架。
5. 不把登录、注册页作为第一阶段重点，只做必要的视觉统一。
