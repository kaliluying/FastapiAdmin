# 只读诊断 Agent

聊天页的“只读诊断 Agent”将一次诊断保存为独立任务。用户选择运行日志、知识库或两者，模型通过受限工具补查证据并生成带引用的报告。普通聊天仍沿用原有连接与会话行为。

## 边界

- 沿用 `module_ai:chat:ws` 权限；任务、进度、结果和取消操作只允许任务本人访问，超级管理员也不能读取他人的任务。
- 运行日志仍仅供超级管理员查询；知识库限定为创建任务时显式选择且当前仍可访问的库，模型不能自行指定其他库。
- 执行前、耗时操作完成后及报告读取时重新校验授权。后台任务绑定发起时的登录会话；退出登录、会话过期、密码变化、用户停用或权限撤销后停止执行。任务不会在新的登录会话下自动续跑，可重新创建。
- 日志、知识内容和模型输出均属于不可信数据。工具只有运行日志查询与知识库检索，不提供 SQL、Shell、文件路径、任意 HTTP 或写操作。
- 任务结果来自工具证据，报告引用格式为 `[1]`。引用编号检查只能验证引用结构，不能证明模型推断正确；报告仍需人工判断。

## 执行与恢复

`ai_agent_run` 保存任务、计数、租约和模型消息检查点；`ai_agent_event` 保存单调递增的进度事件。两张表由 AI 清单显式注册，并由 Alembic 增量迁移创建。

后台 worker 由生产生命周期启动。页面轮询任务快照及增量事件，断线、关闭诊断面板、切换页面或刷新不会取消任务；用户点击取消才更新任务终态。取消会在工具/模型调用前做最后一次持久状态检查，但检查与外部调用之间仍存在不可原子消除的竞态；已准入的调用可能继续至返回或超时，晚到结果不能覆盖取消状态，也不能继续发布进度。

任务领取使用 SQL 锁、条件更新和所有者 token。每个检查点检查当前 token、运行状态和租约；新 worker 接管后，旧 worker 的结果无法写回。正常关闭释放租约，异常退出后租约到期可以恢复。

检查点保存模型提出的工具批次，以及每个已完成工具的返回消息。恢复时只重新执行未保存结果的只读调用。一次工具可能已经完成读取但结果尚未提交，此时允许重读；这一机制不适用于写工具，未来增加写操作必须另行设计审批、幂等与结果核对。

检查点保留 Responses 推理项及工具调用项标识、Anthropic thinking 签名等后续请求所需的协议字段；这些字段仅在服务端保存与回传，不作为公开进度或报告展示。工具参数仍按白名单校验、规范化并脱敏，结构化工具块由校验后的参数重建。关闭面板或详情读取失败时，前端清除已显示的报告、引用和事件，重新授权后从头读取证据。

默认每个任务最多 6 次模型调用、10 次工具调用，每次执行最长 180 秒，租约 210 秒，最多领取 3 次。调用计数在发起调用之前提交，恢复不重置预算。上下文序列化后最多 80,000 字符，最终报告最多 12,000 字符。每人最多 3 个待执行或运行中的任务。用户每日模型调用额度仍由原用量模块核算。

提交编号在用户范围内唯一：相同编号和相同输入返回原任务，相同编号但输入变化返回冲突。网络错误后的重试应保留原提交编号。

## 模块关系与接口

Agent 依赖聊天模块的公开模型及日志接口、知识模块的公开检索接口。聊天模块不反向依赖 Agent；应用由 `module.py` 和 `plugin.toml` 装配。当前没有新增 Agent 框架或任务队列依赖。

| 接口 | 用途 |
| --- | --- |
| `POST /ai/agent/runs` | 提交目标、资料范围及提交编号 |
| `GET /ai/agent/runs` | 读取本人最近任务摘要 |
| `GET /ai/agent/runs/{run_id}?after_seq=0` | 读取快照及指定序号后的事件 |
| `POST /ai/agent/runs/{run_id}/cancel` | 幂等取消本人任务 |

任务摘要不返回内部检查点、登录会话、租约 token 或模型认证信息。列表不返回报告正文与引用；详情重新检查所选资料的可见性。

迁移 `20261024_agent_runs` 仅添加表，不修改原聊天或知识数据。为避免删除历史证据或 bootstrap 创建的表，存在 Agent 表时拒绝自动降级；回退代码和删除诊断历史是不同操作。

## 设计参考与验证

本地样板库 `durable-agent-run-projection` 的稳定任务标识、事件序号和持久进度采用关系库实现；不引入文件投影。`scheduler-reconciliation` 仅参考数据库事实和租约恢复，不引入全局调度 Leader。`contextual-command-surface` 的写入审批留待未来写工具阶段，本版不实现。

自动回归位于 `backend/tests/test_ai_agent_runtime.py`、`backend/tests/test_ai_agent_api.py` 及工具测试；数据库、浏览器和模型接入的验收范围以本轮实际运行报告为准。SQLite/mock 结果不能代替真实 MySQL、PostgreSQL、Redis 与浏览器证据；确定性本地模型只能验证执行链路，不能证明外部供应商兼容性或真实诊断质量。

从 `backend/` 运行：

```sh
.venv/bin/python -m pytest -q tests/test_ai_agent_runtime.py tests/test_ai_agent_api.py tests/test_ai_agent_tools.py
.venv/bin/python -m unittest discover -s integration -p test_agent_acceptance.py
.venv/bin/python integration/agent_acceptance.py --database-type both
```

真实验收脚本使用本机已安装的 Homebrew MySQL 8.4、PostgreSQL 18、Redis 和 Chrome，依赖当前前后端已安装的开发依赖。脚本在系统临时目录创建独立数据库、Redis、配置和前端副本，使用随机本机端口，不加载仓库环境文件，也不连接已有业务数据库；结束后停止子进程，保留 JSON 报告、日志和浏览器截图。可用 `--database-type mysql` 或 `postgresql` 单独复现；`--skip-browser` 仅用于后端排查，不构成完整验收。
