# 2026-07-16 工作日志

## 09:09 — 紧凑侧边栏释放主区域空间

**问题**：用户截图 363x845，反馈"右侧有大面积空白"。

**根因**：sidebar 默认 230px 偏宽，加上 230px 内部 padding (16/18px) + 30px icon 容器 + 12px gap 让侧边栏在窄屏下"显宽"，主区域 1050px 范围内视觉密度低。

**修复**（3 处协同）：

1. **默认宽度收紧**（`config/setting.ts`）：`menuOpenWidth: 230 → 210`，节省 20px 给主区域。

2. **侧边栏内部 padding 紧凑化**（`fa-sidebar-menu/index.vue`）：
   - `.menu-icon` 30×30 → 28×28，font-size 18 → 17px
   - `.menu-item-base` padding `0 16px 0 18px` → `0 12px 0 14px`，margin-right 12 → 10px
   - `.header` padding `0 18px` → `0 14px`，gap 12 → 10px
   - `.header-brand__logo` 38×38 → 36×36，border-radius 10 → 9px
   - `.fa-menu-group-title` padding `20px 18px 8px` → `18px 14px 6px`

3. **中等视口响应式变 200px**（`fa-sidebar-menu/index.vue`）：
   ```scss
   @media (min-width: 801px) and (max-width: 1200px) {
     .layout-sidebar .el-menu:not(.el-menu--collapse) {
       width: 200px !important;  // !important 覆盖 v-bind 的 inline CSS 变量
     }
   }
   ```

4. **主动折叠按钮**（`fa-sidebar-menu/index.vue`）：在 header 右侧加 `.header-collapse-btn`（ri:menu-fold-3-line / unfold-3-line 图标），用户可点击主动收起为 64px 图标模式（节省 146px 给主区域）。折叠态时按钮居中显示。

**关键技巧**：`v-bind(menuopenwidth)` 编译为 `style="--v18004f95: 210px"` + class 规则 `width: var(--v18004f95)`。inline CSS 变量优先级最高，**媒体查询里的 width 覆盖必须用 `!important`**。

**产物验证**：
- `menuOpenWidth: 210` ✓
- `@media(width>=801px) and (width<=1200px) { width: 200px !important }` ✓
- `.header-collapse-btn` 样式编译 ✓

**构建**：`vite build --outDir dist-verify` **✓ built in 2m 39s** 零报错，stylelint --fix 通过。

**视觉效果**（视口 1280px）：
- sidebar 210px（之前 230px）→ 主区域 1070px（+20px）
- 1024px 视口下响应式触发 → sidebar 200px，主区域 824px
- 用户主动点击折叠按钮 → sidebar 64px，主区域 1216px


## 09:54 — 折叠模式隐藏分组标题

**问题**：用户截图反馈侧边栏「只有图标没有文字，分组标题换行很乱」。

**根因**：截图是侧边栏**折叠状态**（用户点击了右上角新增的折叠按钮），但自定义的 `.fa-menu-group-title` 不是 Element Plus 菜单项，不会被自动隐藏，导致「总览 / 系统 / AI 中枢」等标题硬挤在 64px 宽度内换行，且菜单项只显示图标。

**修复**：在 `fa-sidebar-menu/index.vue` 的 `.el-menu--collapse` 规则下增加：

```scss
.el-menu--collapse {
  .fa-menu-group-title {
    display: none;
  }
  // ... 原有折叠样式
}
```

**效果**：折叠模式下只显示图标列，隐藏分组标题，视觉干净；hover 图标时 Element Plus 会自带文字 tooltip。

**构建**：`vite build --outDir dist-verify` **✓ built in 2m 32s** 零报错，stylelint --fix 通过。

**备注**：若用户想回到展开模式，点击 sidebar 顶部 logo 右侧的「展开」按钮即可；默认首次加载仍是展开（`menuOpen: true`）。


## 10:20 — 进一步收紧主内容区 padding，消除右侧空白

**问题**：用户截图反馈「大面积的空白还是没有去掉」。

**根因**：即使 sidebar 已收紧到 210px，主内容区外侧仍有 `#app-content` 的 22px padding + `.layout-content` 的 `margin: auto` + `.page-content` 的 20px padding，三层包裹后实际可用宽度被蚕食；另外首页 `ElRow :gutter="20"` 和 banner 的 30px/34px padding 也制造了过多内部空隙。

**修复**（4 处协同）：

1. **`_fa-layouts.scss` 收紧主内容区包裹层**：
   - `#app-content` padding `22px` → `16px`（大屏）/ `12px`（<=800px / <=640px）
   - `:deep(.layout-content)` `margin: auto` → `margin: 0`，防止 flex item 居中留白
   - `.page-content` padding `20px` → `16px`（大屏）/ `12px`（移动端）

2. **`views/home/index.vue` 收紧栅格间距**：
   - 两个 `ElRow :gutter="20"` → `:gutter="16"`

3. **`views/home/modules/banner.vue` 收紧 banner 内边距**：
   - padding `30px 34px` → `24px 28px`
   - gap `24px` → `20px`
   - 移动端 padding `22px 18px` → `18px 16px`

**效果**：在 1280px 视口 + sidebar 展开 210px 下，主区域可用宽度从约 1014px 提升到约 1044px，且内部包裹层 padding 减少约 22px，卡片排列更紧凑。

**构建**：`vite build --outDir dist-verify` **✓ built in 2m 41s** 零报错，stylelint --fix 通过。

刷新页面即可看到效果。
